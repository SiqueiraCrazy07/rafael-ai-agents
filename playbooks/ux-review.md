# UX Review

## Objetivo

Padronizar revisoes de experiencia para melhorar clareza, usabilidade, acessibilidade, conversao e qualidade mobile.

## Quando usar

- Antes de release de interface.
- Ao revisar fluxo existente.
- Quando houver queda de conversao.
- Quando usuarios reportarem atrito.
- Ao criar nova pagina, formulario ou jornada.

## Agentes envolvidos

- UX Produto
- Frontend Agent
- SEO/CRO Agent
- QA Agent
- PM Estrategico

## Entradas necessarias

- objetivo da tela ou fluxo;
- publico-alvo;
- screenshots ou URL;
- requisitos;
- metricas de conversao;
- feedbacks;
- restricoes tecnicas.

## Passo a passo

1. Identificar objetivo principal do usuario.
2. Mapear jornada e pontos de decisao.
3. Revisar hierarquia visual.
4. Avaliar clareza de texto e chamadas de acao.
5. Validar comportamento mobile.
6. Checar acessibilidade basica.
7. Identificar friccoes e riscos.
8. Priorizar ajustes por impacto x esforco.
9. Definir criterios de aceite de UX.
10. Encaminhar itens para backlog ou correcao.

## Saidas esperadas

- diagnostico de UX;
- lista priorizada de problemas;
- recomendacoes;
- criterios de aceite;
- riscos;
- decisoes abertas.

## Criterios de qualidade

- problemas sao observaveis;
- recomendacoes sao acionaveis;
- mobile foi considerado;
- conversao e clareza foram avaliadas;
- riscos foram priorizados.

## Regras de seguranca

- nao alterar fluxo critico sem validacao;
- nao remover informacao necessaria ao usuario;
- nao sacrificar acessibilidade por conversao;
- revisar impactos em SEO quando a mudanca afetar conteudo.
